## 1. 자기소개

전기·전자 분야를 공부하며 아두이노, PLC, ATmega 등을 활용한 제어 프로그래밍을 접했고, 직접 작성한

코드가 실제 기능으로 동작하는 과정에서 소프트웨어 개발에 관심을 갖게 되었습니다. 대학

졸업작품으로는 OpenCV를 활용한 RC카 자율주행 프로젝트를 진행하며 사용자의 입력과 영상 데이터를

실제 기능으로 구현하는 경험을 했습니다.

이후 소프트웨어 개발을 진로로 선택해 Java 기반 Full-Stack 개발 교육을 수료했으며, 2024년 7월부터 SK

hynix 프로젝트에서 Full Stack Web Developer로 근무하고 있습니다. 현재는 React, Java/Spring, MyBatis,

Oracle을 활용해 화면부터 API와 데이터 처리까지 개발하며, 단순한 기능 구현을 넘어 반복되는 문제를

공통화하고 안정적으로 운영할 수 있는 구조를 고민하고 있습니다.

## 2. 개발자로서의 강점

저의 강점은 반복되는 작업이나 여러 화면에서 공통적으로 발생하는 문제를 개별적으로 처리하기보다,

공통 영역으로 분리해 재사용 가능한 구조로 해결하려는 점입니다.

ELM Portal 프로젝트에서는 여러 화면에서 반복적으로 사용되는 검색 영역과 Form 영역을 공통

컴포넌트로 구현했습니다. 화면마다 동일한 기능을 개별적으로 구현하는 대신 공통 구조로 구성하여 여러

화면에서 재사용할 수 있도록 했습니다. 또한 다중 선택 검색 조건에서 발생할 수 있는 Oracle IN 절 1,000건

제한 문제 역시 특정 화면에서 예외 처리하는 데 그치지 않고, MyBatis 동적 SQL을 활용해 조건을 일정

단위로 분할하고 OR 조건으로 연결하는 공통 SQL 처리 로직으로 구현했습니다.

이러한 경험을 통해 하나의 기능을 구현하는 것뿐 아니라 같은 문제가 다른 화면에서도 반복될 가능성이

있는지, 다른 개발자가 다시 활용할 수 있는 구조인지를 함께 고려하게 되었습니다. 앞으로도 반복되는

로직을 무조건 공통화하기보다 적용 범위와 변경 가능성을 고려하여, 필요한 부분을 적절하게 공통화하고

유지보수하기 좋은 구조를 만드는 개발을 지향하고 있습니다.


## 3. 문제 해결 경험

저는 문제가 발생했을 때 일시적으로 증상을 해결하는 데 그치기보다, 문제가 발생한 원인을 파악하고 처리

구조 자체를 개선하려고 합니다.

ELM Portal 프로젝트에서 대용량 데이터를 조회하거나 Excel로 다운로드하는 과정에서 많은 데이터를 한

번에 처리하면서 서버 메모리 사용량이 증가하고, 서버가 중단되는 문제가 있었습니다. 이를 단순히 서버

자원을 늘리거나 처리 가능한 데이터량을 제한하는 방식으로 대응하기보다, 한 번에 메모리에 적재되는

데이터량을 줄이는 방향으로 처리 구조를 변경했습니다.

일반 조회에는 OFFSET / FETCH 기반의 DB 페이징을 적용하여 현재 페이지에 필요한 데이터만

조회하도록 했고, Excel 다운로드는 전체 데이터를 한 번에 조회해 서비스에서 처리하는 대신 5,000건

단위로 분할 조회하여 순차적으로 처리하도록 개선했습니다. 이를 통해 대용량 데이터를 처리하는

과정에서 발생하던 서버 중단 문제를 해결하고, 한 번에 처리되는 데이터량을 제어할 수 있도록 했습니다.

이 경험을 통해 기능이 정상적으로 동작하는 것뿐 아니라 데이터 규모가 커졌을 때도 안정적으로 동작할 수

있는지 함께 고려해야 한다는 점을 배웠습니다. 이후에도 문제가 발생하면 단순한 우회 방법을

적용하기보다 원인을 확인하고, 데이터 흐름과 처리 방식을 개선할 수 있는 방법을 먼저 고민하고 있습니다.


## 4. 협업 및 업무 경험

입사 초기에는 사수와 함께 업무를 진행하며 요구사항을 분석하는 방법과 프로젝트의 공통 구조, 개발 및

운영 과정에서 필요한 업무 방식을 배웠습니다. 이후 프로젝트 경험이 쌓이면서 후배 개발자와 업무를

나누어 진행했고, 각자 맡은 기능을 개별적으로 개발하는 데 그치지 않고 필요한 데이터 형식과 기능 간

연결 지점을 먼저 맞추며 협업했습니다. 특히 제가 상대적으로 경험이 많았던 React와 퍼블리싱 영역에서는

화면 구조와 공통 컴포넌트 활용 방법을 함께 검토하고, 구현 과정에서 발생하는 문제를 같이 해결했습니다.

최근에는 협업과 개발 생산성을 높이기 위해 AI 기반 개발 도구도 업무에 활용하고 있습니다. SK hynix에서

지원하는 Claude Code를 터미널 환경에서 사용하며 기존 코드 분석, 구현 방향 검토와 개발 과정의 반복

작업을 보조하는 데 활용하고 있습니다. 또한 MCP 연동을 통해 개발에 필요한 도구와 정보를 연결하는

방식도 경험하고 있습니다. AI가 제시한 코드나 해결 방법을 그대로 적용하기보다 기존 프로젝트의 구조와

업무 요구사항에 적합한지 확인하고, 필요한 부분을 직접 수정·검증하는 방식으로 활용하고 있습니다.

이러한 경험을 통해 협업에서는 개인의 역할을 완수하는 것뿐 아니라 서로 알고 있는 내용을 공유하고

결과물이 자연스럽게 연결될 수 있도록 조율하는 과정이 중요하다는 점을 배웠습니다. 앞으로도 동료와

적극적으로 지식을 공유하는 동시에 새로운 개발 도구와 방식을 업무에 적절히 활용하며 팀의 개발 효율과

결과물의 완성도를 함께 높이는 개발자가 되고자 합니다.


## 5. 지원 동기 및 향후 목표

현재까지 기업 업무 시스템을 개발하며 사용자의 요구사항을 기능으로 구현하고, 운영 과정에서 발생하는

문제를 개선하는 경험을 쌓았습니다. React 기반 화면부터 Java / Spring 기반 API와 비즈니스 로직, Oracle

데이터 처리, Workflow, 외부 시스템 Interface, Batch, Dashboard까지 다양한 영역을 경험하며 Frontend와

Backend를 구분하기보다 서비스의 전체 흐름을 이해하고 개발하는 경험을 쌓을 수 있었습니다.

앞으로는 지금까지 쌓은 경험을 바탕으로 다양한 사용자와 요구사항을 가진 서비스의 개발과 개선 과정에

지속적으로 참여하고 싶습니다. 주어진 기능을 구현하는 것에 그치지 않고 사용자가 실제로 서비스를

이용하는 과정과 운영 환경까지 고려하며, 서비스가 성장하고 변화하는 과정에서 발생하는 문제를

해결하는 경험을 넓혀가고자 합니다.

입사 후에는 Java / Spring과 React를 활용한 Full Stack 개발 경험과 공통화 및 데이터 처리 구조를 개선해

온 경험을 바탕으로 새로운 서비스와 도메인을 빠르게 이해하고 기여하겠습니다. 동시에 익숙한 기술에만

머무르지 않고 새로운 기술과 개발 방식을 꾸준히 학습하며, 서비스 전체의 흐름을 이해하고 변화하는

요구사항을 안정적인 시스템으로 구현할 수 있는 개발자로 성장하는 것이 목표입니다.
