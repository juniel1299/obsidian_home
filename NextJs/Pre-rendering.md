# 사전 렌더링

브라우저 요청에 대해 사전에 렌더링이 완료된 HTML을 응답하는 렌더링 방식 

CSR (Client Side Rendering) (리액트의 렌더링 방식) 방식의 단점을 해결 

## CSR 방식 
1. 유저가 서버에 접속 요청
2. 서버가 index.html (빈 내용) 을 브라우저에 전달 
3. 브라우저가 받은 index.html 유저에게 전달
4. 리액트로 만든 JS 파일의 묶음 (JS Bundle)을 브라우저에 전달 
5. 브라우저는 JS 를 리액트로 실행
6. 브라우저가 유저에게 컨텐츠 렌더링해줌

(JS Bundle 안에는 서비스에 존재하는 모든 컴포넌트 코드가 존재 -> 한번 접속하면 서버에 요청 할 필요 x)
- 장점 : 페이지 이동이 매우 빠르고 쾌적하다
- 단점 : FCP (초기 접속 속도)가 느림

## 사전 렌더링 방식
1. 유저가 서버에 접속 요청 
2. 서버에서 JS 실행 (렌더링) (리액트) \[자바스크립트 코드를 HTML 변환\]
3. 서버측에서 브라우저에 렌더링된 HTML(리액트)을 전달 \[화면에 HTML 그림\]
\[단, 아직 인터렉션(상호작용)은 못 함 (HTML 만 그렸기 때문에)\]
4. JS Bundle 을 브라우저에 전달 
5. 브라우저에서 JS 실행 (HTML과 연결) (수화)
6. JS가 연결된 지점까지 유저에게 전달 (TTI 지점) (TTI : 상호작용이 가능한 시점)
- FCP 가 빠름 

- 이후 화면 전환에 대해서는 CSR과 동일함. (애초에 JS Bundle이 React App이기 때문에)


결국 사전 렌더링을 통해 React App이 가진 느린 FCP 해결 + 기존 React App의 빠른 페이지 이동 가짐
