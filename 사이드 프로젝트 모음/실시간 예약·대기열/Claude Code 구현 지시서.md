## 프로젝트 목표

다음자리는 정원이 있는 오프라인 개발 스터디의 회차별 예약과 취소 대기 서비스다. 운영자는 회차와 명단을 관리하고 참가자는 빈자리를 예약하거나 마감된 회차에 대기한다. 최종 완료 기준은 리뷰어가 외부 HTTPS URL을 열어 대기 신청부터 자동 확정까지 혼자 체험할 수 있는 것이다.

## 첫 요청으로 붙여넣을 프롬프트

> 이 문서를 구현 기준으로 사용해 다음자리의 1차 작업을 진행해 줘. 작업 디렉터리와 AGENTS.md, 기존 코드를 먼저 확인하고 기존 구조를 활용해. 저장소가 비어 있다면 작업 디렉터리에 앱을 초기화해. 아래 1차 범위의 화면, API, 데이터베이스, 통합 테스트와 로컬 실행 문서를 완성해. 문서의 기본값은 구현을 시작하기 위한 가정이므로 기존 제약에 맞춰 바꾼 경우 이유를 기록해. 마무리할 때 실행 방법, 실제로 실행한 테스트와 결과, 변경 파일, 후속 작업을 알려줘.

## 1차 구현 범위

- 단일 스터디와 두 역할을 사용한다. 운영자는 회차를 등록하고 확정 명단을 확인한다. 참가자는 회차를 조회하고 본인의 예약을 생성하거나 취소한다. 참가자에게 다른 사람의 신청 정보나 운영자 API 접근을 허용하지 않는다.
- 회차에 제목, 시작 일시, 장소, 정원을 둔다. 시간은 저장·비교 기준을 일관되게 하고 화면에서는 서울 시간으로 표시한다. 시작 시각부터 예약·취소를 거절한다. 정원은 양수다.
- 회차 목록과 상세에서 잔여석을 표시한다. 마감 전 남은 자리가 있으면 서버가 예약을 확정한다. 빈자리가 없으면 마감 상태를 표시한다. 내 예약 상태와 취소 결과를 화면에서 확인할 수 있다.
- 한 참가자는 회차당 활성 신청 한 건만 유지한다. 중복 제출은 활성 건수를 늘리지 않아야 한다. 취소 요청을 반복해도 정원이 두 번 복구되지 않는다. 마감 전 빈자리가 있으면 취소 후 다시 예약할 수 있다.
- 회차 목록·상세 조회, 운영자 회차 생성·명단 조회, 본인 예약 생성·조회·취소 API를 제공한다. 정원 마감, 회차 시작, 권한 부족을 화면에서 구분할 수 있게 오류 응답을 문서화한다.
- 로컬 시드에 운영자, 참가자 두 명 이상, 빈자리가 있는 회차와 마지막 한 자리가 남은 회차를 준비한다. 브라우저에서 운영자와 참가자의 전체 흐름을 확인할 수 있게 한다.

## 구현 기본값

기존 앱 구조가 없다면 Next.js·TypeScript 프런트엔드, Java 17·Spring Boot 3 API, PostgreSQL과 Docker Compose를 사용한다. 스키마 변경은 마이그레이션으로 관리한다. 회차 단위로 예약·취소를 직렬화하는 DB 잠금과 활성 신청의 유일성 제약을 기본안으로 삼는다. 같은 트랜잭션에서 잔여석을 판단하고 신청 상태를 변경한다.

1차 인증은 시드 계정과 서버 세션을 기본안으로 한다. 서버가 세션에서 계정과 권한을 확인하며 요청 본문의 사용자 ID나 역할을 신뢰하지 않는다. 실제 가입·인증 방식과 호스팅 플랫폼은 후속 결정이다.

| 참가자가 브라우저에서 예약하고 취소 | 서버 결과가 상세와 내 상태에 표시되고 다시 열어도 일치 |

## 후속 구현과 공개 데모 목표

- 정원이 찬 회차에 대기를 신청하고 내 순번을 확인한다. 대기 취소 후 재신청하면 맨 뒤로 간다. 확정자가 취소하면 가장 먼저 대기한 참가자가 자동 확정된다. 취소·승격을 한 트랜잭션으로 처리하고, 동시에 신규 예약이 와도 기존 대기자가 우선한다. 정원 증설에도 같은 규칙을 적용하며 확정 인원보다 작게 줄이는 요청은 거절한다.
- 화면 진입과 연결 복구 때 최신 상태를 조회한다. 폴링을 상태 갱신의 초기 후보로 두고 갱신 지연과 부하를 측정한다. 대기 순번과 확정 변화는 키보드 사용자와 보조 기술 사용자에게도 전달한다.
- 공개 HTTPS 주소에서 가입 없이 샘플 체험을 시작할 수 있게 한다. 데모 전용 회차에서 대기 1번으로 신청한 뒤 **샘플 참가자 취소**를 실행해 실제 취소·승격 로직을 체험하도록 한다. 체험 데이터는 방문자별로 격리하고 샘플 조작은 실제 회차에 접근할 수 없게 한다. 격리 방식은 데모 구현 때 정한다.
- 배포 후 모바일과 시크릿 창에서 공개 URL과 시연 흐름을 확인한다. 동시 요청 수, p95 응답 시간과 오류율, 정원·순번 위반 건수를 기록한다. 포트폴리오에 공개 URL, 배포 구조, 검증 결과를 연결한다.
- 결제, 좌석 배치도, 푸시 알림과 서버 접속 대기열은 현재 MVP 범위에서 제외한다.
