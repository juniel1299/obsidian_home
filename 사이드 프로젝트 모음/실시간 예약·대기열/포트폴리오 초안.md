정원이 있는 스터디 회차를 예약하고, 마감된 회차에서는 신청 순서에 따라 취소 자리를 배정받는 웹 서비스입니다. 예약 정합성과 화면 상태 동기화를 구현하고, 가입 없이 핵심 흐름을 체험할 수 있도록 공개 배포했습니다.

무료 서버가 절전 상태이면 첫 체험 진입까지 시간이 걸릴 수 있습니다. 시연 페이지는 백엔드 기동을 기다리지 않고 열립니다.

## 프로젝트 목적과 주요 기능

예약 가능한 마지막 자리에 여러 요청이 동시에 들어오거나, 취소와 신규 예약이 겹치는 상황에서도 정원과 대기 순서를 유지하는 서비스를 만들고자 했습니다. 사용자 화면에서 예약 상태가 바뀌는 과정부터 트랜잭션, 배포 환경의 오류 처리까지 연결하는 것을 목표로 했습니다.

- 참가자는 회차를 예약·취소하고, 마감된 회차에서는 대기 신청과 내 순번 확인을 할 수 있습니다.
- 확정 예약이 취소되거나 정원이 늘어나면 기존 대기자가 순서대로 확정됩니다.
- 운영자는 회차를 등록하고 정원과 확정 명단을 관리합니다.
- 회원가입·로그인·탈퇴를 지원하며, 탈퇴 시 시작 전 예약 취소와 대기자 승격을 처리합니다.
- 방문자는 가입 없이 전용 샘플 회차에서 대기와 자동 승격을 혼자 체험할 수 있습니다.

## 1. 동시 예약과 대기자 승격의 정합성

### 문제

마지막 한 자리에 여러 요청이 동시에 들어오면 정원을 초과할 수 있습니다. 예약 취소와 대기자 승격을 처리하는 중 실패하면 빈자리와 신청 상태가 어긋날 수 있습니다.

### 구현

회차 행에 DB 잠금을 적용해 예약·취소·정원 변경을 처리하고, 활성 신청의 중복은 DB 제약으로 방어했습니다. 취소와 대기자 승격, 정원 증설과 다수 대기자의 승격은 각각 같은 트랜잭션에 포함했습니다. 동일 계정의 반복 예약 요청은 기존 예약을 반환하도록 처리했습니다.

### 검증

PostgreSQL에서 마지막 한 자리에 서로 다른 계정이 요청하면 한 건만 확정되고, 같은 계정이 동시에 요청하면 활성 예약 한 건만 남는지 확인했습니다. 잠금을 제거한 비교 실행에서는 정원 초과와 중복 요청 오류가 발생해 테스트의 검출력을 확인했습니다.

승격 도중 예외를 주입해 취소와 승격이 함께 롤백되는지 검증했습니다. 정원 증설에서도 두 번째 승격 직후 실패하면 정원과 먼저 처리된 승격까지 원상 복구되는 것을 SQL로 확인했습니다.

로컬 M4 Pro·PostgreSQL 16.16 환경에서 대기자 400명이 있는 상태의 혼합 요청 203건을 실행해 636 req/s, p95 288ms를 기록했습니다. SQL 검증에서 정원 초과·활성 신청 중복·대기 추월·승격 누락은 모두 0건이었습니다. 부하 발생기와 서버·DB가 같은 기기에서 실행된 특정 시나리오의 결과이며, 공개 서비스의 처리량은 별도 측정이 필요합니다.

## 2. 예약 상태 동기화와 연결 복구

### 문제

다른 참가자의 취소로 내 대기가 확정돼도 화면이 갱신되지 않으면 변경 사실을 알기 어렵습니다. 숨겨진 탭이나 오프라인 상태에서도 조회를 계속하면 불필요한 요청이 발생합니다.

### 구현

회차 상세 화면이 보이는 동안 5초 간격으로 상태를 조회하고, 탭 복귀와 네트워크 재연결 시 즉시 재조회하도록 구성했습니다. 요청 이후에도 서버 상태를 다시 조회해 잔여석과 신청 상태를 반영했습니다.

### 검증

독립된 두 Chromium 프로세스에서 확정자의 취소 후 대기자의 화면이 페이지 이동 없이 확정으로 바뀌는지 확인했습니다. 로컬에서 폴링 직후 취소하는 조건을 3회 측정한 결과 화면 반영은 약 4.8초였습니다.

숨겨진 탭 6.5초와 오프라인 11초 동안 조회 요청은 각각 0건이었고, 탭 복귀와 재연결 후 상태 반영은 각각 29ms, 27ms를 기록했습니다. 공개 배포에서는 회원 탈퇴로 예약이 취소된 후 대기자의 화면이 4.9초 만에 예약 확정으로 바뀌는 것을 1회 확인했습니다.

## 3. 가입 없는 체험과 무료 배포의 첫 방문 개선

### 문제

대기와 승격을 체험하려면 마감된 회차와 취소를 수행할 다른 참가자가 필요했습니다. 무료 백엔드의 절전으로 첫 접속이 지연되고, 대기 중 버튼 상태가 불명확한 문제도 발견했습니다.

### 구현

방문자별로 샘플 참가자와 마감 회차를 생성하고, 지정된 샘플 예약을 취소해 기존 승격 로직을 실행하도록 구성했습니다. 다른 방문자의 데이터는 서버에서 접근을 제한하고, 만료된 체험 데이터는 정리하도록 했습니다.

첫 화면의 데모 버튼은 로그인 확인을 기다리지 않고 표시합니다. 체험 준비 중에는 중복 클릭을 막고 상태를 안내하며, 서버 기동 중에는 재시도합니다. 최대 대기 시간을 넘기면 오류 안내와 수동 재시도를 제공합니다. 대기 중에도 볼 수 있도록 백엔드 요청 없이 열리는 시연 페이지를 추가했습니다.

### 검증

별도 브라우저 두 개에서 한 방문자의 샘플 취소가 다른 방문자의 대기에 영향을 주지 않는지 확인했습니다.

공개 배포에서 약 55분간 요청이 없던 뒤 첫 방문을 측정했을 때 버튼은 1.6초 만에 표시됐고, 클릭부터 체험 진입까지 170.9초가 걸렸습니다. 반복 클릭과 Enter 입력에도 데모 시작 요청은 한 건만 발생했습니다. 최대 대기 초과와 버튼 복구는 요청 실패·시간 진행 시뮬레이션으로 검증했습니다.

서버가 깨어 있던 별도 측정에서는 iPhone 13 화면 에뮬레이션으로 체험 진입까지 2.1초를 기록했습니다. 두 값은 각각 1회 측정이며 서버 기동 시간과 모바일 실기기 성능을 일반화할 수는 없습니다.

## 인증과 계정 처리

서버 세션과 CSRF 검증을 적용하고 운영 환경의 세션은 PostgreSQL에 저장했습니다. 프록시 전달 헤더를 위조해 로그인 제한을 우회하는 문제를 재현한 뒤, 배포 구조에 맞게 요청 출처 확인과 전달 헤더 처리를 수정했습니다. 실패 횟수는 DB에서 원자적으로 집계합니다.

탈퇴 시 비밀번호를 재확인하고, 시작 전 예약 취소·대기자 승격·계정 익명화·기존 세션 접근 차단을 처리했습니다. 공개 배포에서 탈퇴 계정의 로그인 거절과 대기자의 자동 확정을 확인했습니다.

## 테스트와 현재 한계

백엔드 306개와 브라우저 테스트 41개가 통과한 기록을 확보했습니다. 이는 2026.11.21 커밋 `548023aa` 기준의 직전 실행 결과입니다. 이후 문서·시연 자료 변경까지 모두 재실행한 결과로 표기하지 않았습니다.

실제 사용자 수와 사업 성과는 수집하지 않았습니다. 공개 서버의 본격적인 부하 검증, 실제 iPhone Safari 영상 재생, 공개 운영자 화면은 확인 대기입니다. 폴링에 따른 갱신 지연과 무료 서버의 첫 접속 대기는 현재 운영상의 한계입니다.

## AI 활용

개인 프로젝트로 진행하며 Codex와 Claude Code를 기획, 구현, 테스트, 오류 수정, 문서 작성에 활용했습니다. AI와의 협업 과정에서 요구사항과 검증 결과를 반복적으로 검토하며 서비스를 완성했습니다. 특히 공개 사이트에서 발견한 데모 버튼 상태와 회원가입·탈퇴 동선 문제를 수정 요구사항으로 구체화해 개선했습니다.

## 지원 직무에 따른 강조점

- **프런트엔드** 지원 시 화면 상태 동기화, 연결 복구, 로딩·오류 처리와 브라우저 검증을 중심으로 설명합니다.
