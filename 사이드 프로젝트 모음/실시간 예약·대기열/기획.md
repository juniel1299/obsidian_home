# 다음자리 — 오프라인 개발 스터디 예약·취소 대기 서비스

2026-11-15 · 기획 완료 초안 · 구현 미착수 · 구현 기준 [[Claude Code 구현 지시서]]

**한 줄 소개:** 정원이 있는 개발 스터디 회차를 예약하고, 마감된 회차는 대기 신청해 취소 자리를 신청 순서대로 받는다.

**대상 가설:** 매주 8~20명이 모이는 개발 스터디 운영자와 참가자. 단체 채팅에서 참석 댓글과 취소 메시지를 모아 명단을 갱신하는 수고를 줄인다. 실제 운영자 1명 이상에게 마감 빈도, 취소 처리 방식, 자동 확정 허용 여부를 확인한다.

## MVP 기능과 사용자 흐름

| 기능 | 동작 |
|---|---|
| 회차 조회 | 참가자는 회차별 일시, 장소, 정원과 예약 가능 여부를 본다. |
| 예약·취소 | 남은 자리가 있으면 즉시 확정된다. 계정당 회차별 활성 신청은 한 건이다. 확정 예약과 대기 신청 모두 취소할 수 있다. |
| 취소 대기 | 마감된 회차에 신청하면 내 대기 순번이 표시된다. 취소 후 재신청하면 맨 뒤로 간다. |
| 자동 재배정 | 확정자가 취소하면 가장 먼저 신청한 유효 대기자가 자동 확정된다. 이 정책은 대기 신청 전에 안내한다. 대기자가 없으면 일반 예약이 다시 열린다. |
| 내 신청 상태 | 확정·대기·취소 상태를 보여 준다. 화면을 다시 열거나 연결이 복구되면 최신 서버 상태를 조회한다. |
| 운영자 관리 | 회차를 등록하고 시작 전 참가자·대기 명단을 확인한다. 확정 인원보다 작게 정원을 줄일 수 없으며, 정원을 늘리면 남는 자리만큼 대기자를 순서대로 확정한다. |

예: 12명 정원이 찼을 때 민지가 대기 1번, 준이 2번이다. 확정자 한 명이 취소하면 민지는 확정, 준은 대기 1번이 된다. 같은 순간 새 예약 요청이 들어와도 기존 대기자가 먼저다.

초기 정책안: 회차 시작 시각에 예약·대기·취소·승격을 마감한다. 앱 안에서 상태를 확인한다. 결제, 좌석 배치도, 채팅, 이메일·푸시, 대기 제안 수락 타이머, 운영자의 임의 순번 변경, 대규모 접속 대기열은 보류한다. 취소 대기는 회차의 빈자리를 기다리는 제품 기능이다.

## 기술 후보

- 1차 후보: Next.js/TypeScript, Java 17/Spring Boot 3, PostgreSQL, Docker Compose. 익숙한 웹 기술을 쓰고 DB 트랜잭션에서 예약과 재배정을 함께 처리해 실패 시 함께 되돌린다. 회차 단위 잠금과 DB 제약을 후보로 삼고 실제 동시 요청 테스트 후 확정한다.
- 상태 갱신: 화면 진입·재연결 시 재조회와 짧은 폴링으로 시작한다. 목표 갱신 시간과 조회 부하를 측정하고, 필요하면 서버에서 화면으로 보내는 SSE를 비교한다. 양방향 WebSocket, Redis, 메시지 큐는 측정으로 필요가 드러날 때 검토한다.
- 결정(1차 기본안): 제목 '다음자리'와 개발 스터디 도메인, 단일 스터디와 운영자·참가자 두 역할, 회차 시작 시각 마감, 대기자 자동 확정, 시드 계정과 서버 세션 로그인. 세부는 [[Claude Code 구현 지시서]]를 따른다.
- 미정: 실제 테스트할 스터디, 실제 가입·인증 방식, 배포 환경, 갱신 시간 목표, 데모 체험 데이터 격리 방식, 구현 저장소 위치.
