## 검증 기준

- 정원 1석에 여러 계정이 동시에 예약해도 1건만 확정된다. 같은 계정의 중복 요청으로 활성 신청이 늘어나지 않는다.
- 동시 취소·신규 예약에서도 기존 대기자가 순서대로 한 번만 승격된다. 취소와 승격 사이에서 실패하면 일부만 반영되지 않는다.
- 참가자와 운영자 권한을 구분한다. 참가자는 명단 전체를 볼 수 없고, 운영자는 담당 회차만 관리한다.
- 연결 복구 후 서버 상태와 화면이 일치한다. 키보드로 예약 흐름을 완료하고 상태 변화를 보조 기술로 확인할 수 있다.
- 부하 시험에는 동시 요청 수, p95 응답 시간, 오류율, 정원·순번 위반 수를 남긴다. 정원·순번 위반 허용치는 0건이며 속도 목표는 시험 전에 정한다.
- 포트폴리오 증거: 프런트엔드는 상태 갱신·접근성 시연, 백엔드는 동시성·실패 복구 결과, 풀스택은 배포된 사용자 흐름과 운영 지표를 남긴다.

## Claude Code 첫 구현 지시서의 선행 조건

2026-11-15 점검: 1·4 충족, 2·3 일부 충족. 남은 항목은 각 줄의 *현황*에 적는다.

1. 제목과 대상 도메인, 단일 스터디 운영 범위, 계정·권한 모델, 마감과 자동 확정 정책을 결정한다. *현황: 충족. 지시서에 반영.*
2. 회차·신청 상태 전이표와 정원·중복 불변조건을 정한다. 정원 초과, 중복 요청, 마감, 취소 뒤 재신청의 응답을 API 계약에 적는다. *현황: 일부. 불변조건과 오류 구분 요구는 지시서에 있다. 상태 전이표와 응답 코드 수준의 API 계약은 구현 단계에서 README에 문서화하는 것으로 넘겼다.*
3. 구현 저장소 위치, 기본 스택, 로컬 실행 환경, 샘플 회차와 계정, 통합 테스트 실행 방법을 지정한다. *현황: 일부. 기본 스택, 시드, 인수 테스트는 지정했다. 구현 저장소 위치는 사용자가 추후 지정한다.*
4. 첫 작업 범위는 회차 등록·조회와 정원 내 예약·취소로 제한한다. 마감, 권한, 마지막 한 자리 동시 요청의 인수 기준을 포함한다. 대기·승격은 후속 작업으로 분리하되 첫 작업의 데이터 모델이 이를 막지 않는지 검토한다. *현황: 충족. 지시서의 1차 구현 범위와 후속 구현으로 분리했다.*

## 포트폴리오 공개 데모 완료 기준

- 7주차 산출물은 외부에서 접속할 수 있는 HTTPS URL이다. 10주차에는 포트폴리오에서 이 URL로 바로 연결한다. 호스팅 환경은 미정이며 URL은 배포 후 기록한다.
- 시크릿 창과 모바일에서 데모에 진입하고 샘플 회차를 체험할 수 있는지 확인한다. 마감 회차에 대기를 신청하고 빈자리 재배정으로 상태가 바뀌는 흐름을 혼자 재현할 수 있게 한다. 리뷰어에게 개인 계정 생성을 요구하지 않는 데모 접근 방식을 설계한다.
- 프런트엔드 증거는 대기 신청 직후와 재배정 후 화면, 연결 복구 뒤 상태 갱신, 키보드 조작이다. 백엔드 증거는 마지막 한 자리 경쟁과 기존 대기자 우선 처리에 대한 동시성 테스트 및 실측 결과다. 풀스택 증거는 공개 URL에서 실행되는 전체 흐름과 배포 구조, 운영 지표다.
- 8~9주차에 공개 배포본의 접속과 시연 흐름을 검증하고, 실제 운영자나 참가자에게 받은 피드백이 있으면 범위와 개선점을 기록한다. 공개 접속 가능 여부와 실제 사용자 사용 실적은 별도로 기록한다.
